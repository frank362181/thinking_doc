## 1. 认证体系：从用户输入到LLM请求
### Pi的认证分为两层：
1. coding-agent层：AuthStorage + ModelRegistry -- 持久化凭证、解析per-Provider / per-model配置
2. pi-ai层：CredentialStore + AuthContext + ProviderAuth -- 统一的认证抽象

### 1. AuthStorage

文件：packages/coding-agent/src/core/auth-storage.ts
AutoStorage是~/.pi/agent/auth.json的封装，同时支持运行是覆盖（如 --api-key）

auth.json的大致结构：

    {
        "anthropic": {
            "apiKey": "sk-ant-..."
        },
    
        "github-copilot":{
            "oauth":{
                "token":"ghu_....",
                "eppiresAt":"2026-09-09T10:43:21:00Z"
            }
        },
        
        "openai":{
            "apiKey":"sk....",
            "env":{
                "OPENAI-BASE_URL":"https://custom.example.com"
            }
        }
    }

// AutoStorage是对 auth.json的封装

    export class AuthStorage {
        static create(authPath?: string): AutoStorage;
    
        //持久化API可以（如login保存）
        async setApikey(provider: string, apiKey: string): Promise<void>;
    
        //运行时覆盖，不写入磁盘，如(--api-key)
        setRuntimeApiKey(provider: string, apiKey: string): void;
    
        //读取 API Key
        async getApiKey(provider: string,options?:{includeFallback?: boolean}):Promise<string | undefined>;
    
        //provider 级别的 env 覆盖
        async getProviderEnv(provider: string): Promise<Record<string, string> | undefined>;
    
        // OAuth相关
        async setOAuth(provider: string, credential: OAuthCredential): Promise<void>;
        async getOAuth(provider: string): Promise<OAuthCredential | undefined>;
    }

### 2 ModelRegistry

文件：packages/coding-agent/src/core/model-registry.ts

ModelRegistry把AutoStorage、settings中的provider配置、CLI参数结合在一起，为每个模型请求解析出最终的认证信息

    export interface ModelRegistry {
        getApiKeyAndHeaders(model: Model<Api>): Promise<ResolvedRequestAuth>;
        hasConfiguredAuth(model: Model<Api>): boolean;
        isUsingOAuth(model: Model<Api>): boolean;
        setProviderRequestConfig(provider: string, config: ProviderRequestConfig): void;
        setModelRequestHeaders(provider: string, modelId: string, headers: Record<string, string>): void;
    }

### 3 认证解析的优先级

对于一次LLM请求，ModelRegistry.getApiKeyAndHeaders(model)按以下顺序解析：
- runtime覆盖：CLI --api-key通过AuthStorage.setRuntimeApiKey()设置；
- auth.json中的API Key / OAuth token
- settings中的Provider配置：providerRequestConfigs里的apiKey(支持env覆盖)
- per-model请求头： modelRequestHeaders
- 环境变量： pi-ai的 envApiKeyAuth作为fallback

如果最终没有可用凭证，返回ok: false，coding-agent会抛出有好的错误提示（auth-guidance.ts）

### 4. Provider级别的 env覆盖
v0.79支持特定的provider配置 env覆盖：

    {
        {
            "openai": {
                "apikey": "$OPENAI_API_KEY",
            }
            "env":  {
                "OPENAI_BASE_URL": "https://my-proxy.example.com"
            }
        }
    }
这些 env 值只在该Provider的LLM请求中生效，不会污染全局进程环境

## 2 pi-ai的认证抽象

目录：packages/ai/src/auth/

### 1 ApiKeyAuth

    export interface ApiKeyAuth {
        name: string;
        resolve(authContext: AuthContext): Promise<ApiKeyCredential | undefined>;
    }
envApiKeyAuth() 是最常见的实例：
envApiKeyAuth('OpenAI API Key',['OPENAI_API_KEY']);

### 2 OAuthAuth
    export interface OAuthAuth {
        name: string;
        login(authContext: AuthContext): Promise<OAuthCredential>;
        refresh(credential: AuthCredential,authContext: AuthContext): Promise<OAuthCredential>;
        toAuth(credential: OAuthCredential): Promise<RequestAuth>;
    }
lazyOAuth({name: 'GitHub Copilot', load: loadGithubCopilotAuth});

### 3 CredentialStore
pi-ai的Models运行是内部使用 CredentialStore;

    export interface CredentialStore {
        read(providerId: string): Promise<StoredCredential | undefined>;
        modify(providerId: string, fn: (current?: StoredCredential) => StoredCredential | undefined): Promise<void>;
        delete(providerId: string): Promise<void>;
    }
coding-agent传入的是AuthStorage的适配器，使得pi-ai的读写最终落到 ~/.pi/agent/auth.json
