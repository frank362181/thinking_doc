## 1. 项目信任机制
- 项目信任机制：为何需要项目信任机制？ 
  - 需要加载本地多种资源：如 配置、扩展、skills、prompts等；
  - 引导文件：AGENTS.md、SOUL.md、TOOLS.md等

- 项目信任的数据流：
  - 启动/切换 cwd 
  - 检查cmd是否有trust-requiring资源 
  - 查询ProjectTrustStore(~/.pi/agent/trust.json)
  - 若已信任 ->直接加载项目资源
  - 若未决策：
    - 触发project-trust扩展事件（user/global/CLI扩展可参与决策）
    - 若扩展未处理，弹出TUI选择器（界面）
    - 用户选择：始终信任 / 仅本次信任 / 从不信任
    - 持久化决策（除“本次外”）
- 核心模块
  - ProjectTrustStore 与 TrustManager
    
    文件位置：packages/coding-agent/src/core/trust-manager.ts
  - TrustManager 负责：
    - 记录每个cwd的信任状态
    - 判断当前项目是否有需要信任的资源
    - 提供信任选项（始终信任、仅本次、从不、记住本次）
    
        export interface ProjectTrustStore {
            isTrusted(cwd: string): boolean;
            isDenied(cwd: string): boolean;
            setTrusted(cwd: string): void;
            setDenied(cwd: string): void;
            remove(cwd: string): void;
        }
  - resolveProjectTrusted
    
    文件位置：packages/coding-agent/src/core/project-trust.ts，这是项目信任的入口函数
    export interface ResolveProjectTrustOptions {
        cwd: string;
        trustStore: ProjectTrustStore;
        trustOverride?: boolean; //CLI-approve,or non
        defaultProjectTrust?: DefaultProjectTrust; //全局默认安全机制
        extensionsResults?: LoadExtensionsResult;
        projectTrustContext: ProjectTrustContext;
        onExtensionError?: (message: string) => void;
    }

    流程：
    - 如果trustOverride 为true,直接使用该覆盖模式
    - 否则检查defaultProjectTrust设置（ask/always/never）
    - 否则检查trustStore中是否已经有决策；
    - 否则触发project_trust扩展事件；
    - 否则弹出TUI选择器

  - project-trust扩展事件
  
    文件：packages/coding-agent/src/core/extensions/types.ts
    扩展可以监听project_trust事件，在UI提示前决定或推迟信任
    
    pi.on('project_trust', async(event,ctx) => {
        // event.cwd --当前工作目录
        // event.projectTrustContext -- 信任上下文
        // 返回 action : trust | deny | defer
        return {action: 'trust'};
    })
  
    只有user/global/CLI扩展能参与project_trust；项目本地扩展此时还未加载。
  - defaultProjectTrust设置
    
    可以在setting.json中设置：
    
    {
        "defaultProjectTrust": "ask"    
    }
